# NFR Framework — Usabilidade

## NFR01: Usabilidade

### Descrição

O NFR01 representa o atributo de qualidade **Usabilidade** no contexto do
**G2 — Fórum**, uma plataforma de discussão e compartilhamento de
conhecimento.

O Softgoal Interdependency Graph (SIG) é utilizado para representar
graficamente as relações entre o requisito não funcional de Usabilidade,
seus respectivos softgoals e as operacionalizações que podem contribuir
para sua satisfação.

Neste trabalho, o SIG foi elaborado considerando especificamente o
**fluxo de Login** da plataforma, representado anteriormente por meio do
artefato generalista **Rich Picture**.

A escolha de Usabilidade como atributo de qualidade está relacionada ao
objetivo do G2 — Fórum de proporcionar uma experiência simples, intuitiva
e acessível aos seus usuários.

---

### Contexto

O processo de Login representa uma das principais portas de entrada do
usuário no G2 — Fórum. Dessa forma, problemas relacionados à clareza das
informações, facilidade de preenchimento, feedback das ações ou tratamento
de erros podem comprometer diretamente a experiência de uso da plataforma.

A partir da análise da tela de Login representada na Rich Picture, foram
identificados aspectos que podem ser relacionados ao atributo de qualidade
**Usabilidade**.

Entre eles estão:

- facilidade para compreender os campos necessários para autenticação;
- facilidade para realizar o preenchimento das informações;
- clareza das mensagens apresentadas ao usuário;
- feedback após uma tentativa de Login;
- identificação e recuperação de erros;
- facilidade para recuperar o acesso à conta;
- consistência dos elementos da interface.

Esses aspectos são utilizados como base para a construção do SIG de
Usabilidade.

---

### Requisitos Não Funcionais

Os seguintes requisitos não funcionais foram considerados para a
composição do SIG:

- **RNF01 — Facilidade de Uso:** A tela de Login deve apresentar uma
  interface simples e intuitiva, permitindo que o usuário compreenda
  facilmente quais informações devem ser fornecidas.

- **RNF02 — Clareza das Informações:** Os campos, botões e instruções
  presentes na tela de Login devem possuir identificação clara e
  compreensível.

- **RNF03 — Feedback ao Usuário:** O sistema deve apresentar feedback
  adequado após as ações realizadas durante o processo de Login.

- **RNF04 — Tratamento de Erros:** O sistema deve informar de maneira
  clara quando ocorrer um erro durante a autenticação, permitindo que o
  usuário compreenda o problema e tente novamente.

- **RNF05 — Recuperação de Acesso:** O sistema deve disponibilizar um
  mecanismo simples para recuperação de acesso quando o usuário não
  lembrar suas credenciais.

- **RNF06 — Consistência da Interface:** Os elementos da interface do
  Login devem apresentar comportamento e organização consistentes com
  os demais elementos da plataforma.

## Decomposição do Softgoal

### Facilidade de Uso

A facilidade de uso está relacionada à capacidade do usuário de compreender
e utilizar a tela de Login sem dificuldades desnecessárias.

Para esse softgoal, são consideradas características como:

- organização clara dos campos;
- identificação adequada dos campos;
- linguagem simples;
- disposição intuitiva dos elementos;
- redução da quantidade de ações necessárias para realizar o Login.

### Clareza das Informações

A interface deve apresentar informações suficientemente claras para que
o usuário compreenda o que precisa fazer durante o processo de autenticação.

São consideradas operacionalizações como:

- utilização de rótulos nos campos;
- instruções objetivas;
- identificação clara dos botões;
- mensagens compreensíveis.

### Feedback ao Usuário

O sistema deve informar ao usuário o resultado das ações realizadas durante
o processo de Login.

Exemplos de operacionalizações:

- apresentar mensagem após tentativa de autenticação;
- informar quando o Login foi realizado com sucesso;
- informar quando as credenciais são inválidas;
- indicar visualmente situações de carregamento.

### Prevenção e Recuperação de Erros

O sistema deve auxiliar o usuário na identificação e correção de problemas
durante o processo de autenticação.

Podem ser utilizadas as seguintes operacionalizações:

- validação dos campos antes do envio;
- indicação de campos preenchidos incorretamente;
- mensagens de erro específicas;
- possibilidade de corrigir os dados sem reiniciar o processo;
- disponibilização de recuperação de senha.

### Consistência

A interface de Login deve manter padrões visuais e comportamentais
consistentes com o restante da plataforma.

Entre as operacionalizações estão:

- utilização consistente de botões;
- padronização dos campos de entrada;
- manutenção dos padrões de navegação;
- utilização de elementos visuais coerentes com a identidade do G2 — Fórum.

---

## Operacionalizações

As operacionalizações representam possíveis soluções ou mecanismos que
podem contribuir para a satisfação dos softgoals de Usabilidade.

| Softgoal | Operacionalização |
|---|---|
| Facilidade de Uso | Organizar os campos de Login de forma simples e intuitiva |
| Clareza das Informações | Utilizar rótulos e instruções objetivos |
| Feedback ao Usuário | Apresentar mensagens de sucesso, erro e carregamento |
| Prevenção de Erros | Validar os campos antes do envio |
| Recuperação de Erros | Apresentar mensagens que indiquem como corrigir o problema |
| Recuperação de Acesso | Disponibilizar opção de recuperação de senha |
| Consistência | Utilizar padrões visuais e componentes consistentes |

---

## Justificativas

A **Facilidade de Uso** foi considerada necessária porque o Login
representa uma etapa inicial de interação do usuário com o sistema.
Uma interface complexa pode dificultar o acesso à plataforma.

A **Clareza das Informações** contribui para reduzir dúvidas durante o
preenchimento dos dados de autenticação, deixando explícito o que deve ser
informado em cada campo.

O **Feedback ao Usuário** é importante para que o usuário compreenda o
resultado de suas ações. Sem feedback adequado, uma tentativa de Login
pode parecer não ter sido processada.

A **Prevenção e Recuperação de Erros** permite reduzir a frustração
causada por informações incorretas e auxilia o usuário a corrigir os
dados fornecidos.

A **Recuperação de Acesso** é importante porque usuários podem esquecer
suas credenciais. A existência de um mecanismo específico para recuperação
reduz as dificuldades para retornar à plataforma.

Por fim, a **Consistência** contribui para que o usuário reconheça padrões
de interação e consiga utilizar a interface de maneira mais previsível.

---

## Relações no NFR Framework

No SIG, o softgoal principal **[Usabilidade]** é decomposto em diferentes
aspectos relacionados à experiência do usuário no processo de Login.

A relação entre os softgoals e as operacionalizações deve representar como
cada solução contribui para a satisfação do requisito de qualidade.

As contribuições devem ser classificadas utilizando a notação adotada pelo
NFR Framework, indicando contribuições positivas, negativas ou de outra
natureza quando aplicável.

---

## Considerações Finais

A utilização do NFR Framework para representar a **Usabilidade** permite
explicitar como diferentes características da interface de Login podem
contribuir para a qualidade da interação do usuário com o G2 — Fórum.

A análise não se limita à aparência da interface, considerando também
aspectos relacionados à compreensão das informações, feedback, tratamento
de erros, recuperação de acesso e consistência.

O SIG poderá ser refinado durante o desenvolvimento do projeto, conforme
novos requisitos, decisões de design e resultados das avaliações de
Usabilidade sejam identificados.
